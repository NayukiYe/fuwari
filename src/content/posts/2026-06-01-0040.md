## 🧩 从「搬服务器」说起

想象一下，你要部署一个 Web 应用。你需要：
1. 装一个 Linux 系统
2. 安装 Python/Node.js/Java 运行环境
3. 配置数据库
4. 装各种依赖库
5. 把代码放上去
6. 配置网络和防火墙

光是第一步，在不同的服务器上就可能遇到各种问题——这个系统的包管理器不一样，那个系统的内核版本太低，这个库版本冲突……这就是经典的 **「在我电脑上明明可以跑啊！」** 问题 😂

## 📦 Docker 怎么解决？

Docker 的核心思想很简单：**把你的应用和它需要的所有环境打包成一个「容器镜像」**，然后这个镜像可以在任何装了 Docker 的机器上直接运行，不管底层是什么系统。

```
┌─────────────────────┐
│   你的应用代码       │
│   Python/Node.js    │
│   系统库 & 依赖      │
│   Ubuntu/Alpine     │
│   Docker Engine     │
│   宿主机操作系统     │
│   硬件               │
└─────────────────────┘
```

每一层都可以复用。比如你用 Ubuntu 作为基础镜像，那所有基于 Ubuntu 的容器都共享同一份底层文件，不占额外空间。

## 🐳 常用命令速记

```bash
# 拉取镜像
docker pull nginx:latest

# 运行容器
docker run -d -p 8080:80 --name my-web nginx

# 查看运行中的容器
docker ps

# 进入容器内部
docker exec -it my-web bash

# 构建自己的镜像
docker build -t my-app:1.0 .

# 用 docker-compose 一键启动全套服务
docker compose up -d
```

## 🏗️ 容器 vs 虚拟机

| 特性 | 容器 | 虚拟机 |
|:----|:----|:-------|
| 启动速度 | 秒级 ⚡ | 分钟级 🐢 |
| 资源占用 | 轻量（MB级） | 重量（GB级） |
| 内核 | 共享宿主机内核 | 独立内核 |
| 隔离性 | 进程级隔离 | 完全隔离 |
| 一个机器能跑 | 几十上百个 | 几个到十几个 |

简单来说：**虚拟机是模拟了一整台电脑，容器只是把你的应用装进了一个隔离的「小盒子」里。**

## 🔄 现在的主流玩法

现在的云原生架构通常长这样：

```
开发 → Dockerfile → 镜像仓库(Registry) → 容器编排(K8s) → 生产环境
```

- **Docker**：把应用打包成镜像
- **Docker Hub / Harbor**：存镜像的地方
- **Kubernetes (K8s)**：管理成千上万个容器的编排平台
- **docker-compose**：本地开发时编排多个容器
