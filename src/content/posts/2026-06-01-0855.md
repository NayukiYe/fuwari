## fork() — 进程的诞生

在 Linux 世界里，创建新进程只有一个方式：`fork()`。它会完整复制当前进程，创建一个一模一样的子进程。子进程从 `fork()` 的返回点继续执行，唯一不同的是——`fork()` 对父进程返回子进程的 PID，对子进程返回 0。

```c
pid_t pid = fork();
if (pid == 0) {
    // 子进程：在这里干你的活
    execlp("ls", "ls", "-la", NULL);
} else if (pid > 0) {
    // 父进程：等孩子干完活
    waitpid(pid, NULL, 0);
}
```

配合 `exec` 系列函数，子进程可以"变身"成另一个程序——这就是 shell 执行命令的底层机制。每次你在终端敲 `ls`，bash 就在背后 fork + exec 了一次。

## 进程的五种状态

Linux 进程有五种核心状态，用 `ps aux` 的 STAT 列可以看到：

| 状态 | 含义 | 例子 |
|------|------|------|
| **R** (Running) | 正在运行或在运行队列中 | 正常工作的进程 |
| **S** (Sleeping) | 可中断睡眠，等待事件 | 等待网络 I/O |
| **D** (Disk Sleep) | 不可中断睡眠，通常等磁盘 | 等磁盘读写完成 |
| **T** (Stopped) | 暂停，收到 SIGSTOP | 调试中 `Ctrl+Z` |
| **Z** (Zombie) | 僵尸，已退出但未被回收 | 👻 经典 bug |

## 僵尸进程：编程里的「鬼故事」

僵尸进程是面试最爱问的话题之一。简单说——子进程已经退出了，但父进程还没调用 `wait()` 来回收它的退出状态。这时候子进程的 PCB（进程控制块）还残留在内核里，占着 PID 不放。

```bash
# 排查僵尸进程
ps aux | grep 'Z'
# 或者
top -b -n1 | grep zombie
```

**解决方法**：
1. 让父进程调用 `wait()` 或 `waitpid()`
2. 用 `SIGCHLD` 信号异步回收
3. 如果父进程也不在了，僵尸会被 `init`（PID 1）收养并清理

## 实用命令速查

```bash
# 查看所有进程
ps aux                 # BSD 风格
ps -ef                 # Unix 风格

# 实时监控
top                    # 交互式
htop                   # 更好看（需安装）

# 进程树
pstree -p              # 看清楚父子关系

# 结束进程
kill -9 PID            # 强制杀死（SIGKILL）
kill -15 PID           # 优雅退出（SIGTERM）
killall -9 进程名       # 按名字杀

# 后台运行
nohup command &        # 退出终端也不断
Ctrl+Z → bg            # 暂停后放后台
```

## 进程 vs 线程

很多人搞混进程和线程，记住一句话就够了：**进程是资源分配的最小单位，线程是 CPU 调度的最小单位。** 同一个进程的线程共享内存空间（所以通信方便但容易互相踩到），不同进程的内存是隔离的（更安全但通信要用 IPC）。
