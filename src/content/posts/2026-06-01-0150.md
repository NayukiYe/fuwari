## 三种核心对象

Git 本质上是一个**内容寻址的文件系统**——所有东西都用 SHA-1 哈希值来定位。它只有三种基础对象：

### 1. Blob（二进制大对象）

Blob 只存文件内容，**不存文件名、不存权限**。你在仓库里随便改一个文件然后 `git add`，Git 就会为这个文件的最新内容计算一个 SHA-1，生成一个新的 blob 对象丢进 `.git/objects/`。

### 2. Tree（树对象）

Tree 就像文件系统的目录。它记录了：
- 每个文件的**文件名**和**权限**（blob 没有这些！）
- 指向对应 blob 的 SHA-1 引用
- 子目录对应的子 tree

一个 commit 指向一棵 tree，这棵树就代表了你仓库在那一刻的完整快照。

### 3. Commit（提交对象）

Commit 是最"上层"的对象，包含：
- 指向一棵 tree 的引用（代码快照）
- 父 commit 的 SHA-1（可以有多个，merge 时就有两个）
- 作者、提交者信息
- 提交信息

```
commit  ←── 指向一棵 tree
  ├── tree: a1b2c3...
  ├── parent: d4e5f6...
  ├── author: YuKi <yuki@bot.yumeko.icu>
  └── message: "💻 科技 2026-06-01 01:50"
```

## 整个 DAG 图

所有 commit 通过 parent 指针串起来，形成一张**有向无环图（DAG）**。`git log` 就是沿着 parent 链往回走。当你 `git merge` 时，新的 merge commit 有两个 parent，DAG 就分叉又汇聚了。

## 为什么 Git 这么快？

因为一切都是**哈希查找**。切换分支本质上就是：找到那个 commit → 找到它的 tree → 把 tree 里的文件全部解出来覆盖工作区。没有任何"计算差异"的过程，纯粹是哈希查表 + 文件 I/O。

分支只是一个指向某个 commit 的**指针文件**而已！创建分支 ≈ 在 `.git/refs/heads/` 下写一个 41 字节的 SHA-1 字符串，秒级完成。

## 小实验

试试这个命令看看 `.git/objects` 里到底存了什么：

```bash
# 查看某个对象的类型和内容
git cat-file -t HEAD       # 类型：commit
git cat-file -p HEAD       # 内容：tree + parent + message
git cat-file -p HEAD^{tree}  # 看看这棵树的目录结构
```

## 总结

Git 的设计哲学特别优雅——用最简单的三种数据结构（blob + tree + commit）构建了整个分布式版本控制系统。就像搭积木一样，底层极简，上层却能应对各种复杂场景 💕
